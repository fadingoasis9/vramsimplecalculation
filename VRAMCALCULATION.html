模型显存

不用背复杂术语：先算“模型本身”要占多少显存，再根据推理或训练场景，加上聊天缓存和训练过程的额外占用，就能快速判断模型大概需要多少显存。

模型本身（FP16 / BF16）1B 参数 ≈ 2GB（约 1.86GiB）
推理时模型本身 + 聊天缓存 + 临时工作空间
全量训练显存（AdamW）约 16–20 bytes / 参数 + 激活
先记住模型本身只是最低占用，装得下不等于一定跑得稳

模型参数

参数是模型在训练过程中学到的可学习数值，可以理解为大脑里的“神经连接强度”。

Weights

权重

用于衡量输入信号的重要程度。通常我们说 7B / 13B / 70B，指的就是 70 亿 / 130 亿 / 700 亿个参数权重。

Bias

偏置

在加权求和后额外加的常数，用于调整输出整体偏移。简单说：不管输入是什么，先给一个基础倾向。

Rule of thumb

参数越多 ≠ 越划算

参数越多，模型记住的模式越多，能力上限可能越高。但记忆多不等于思考快，也不等于成本低。

模型精度

精度指单个参数用多少 bit 存储和计算：数字写得越精细，显存越贵。

FP32
4B

32 bit

早期默认。精度高、稳定，但显存太贵，现在几乎不用来跑大模型。

FP16 / BF16
2B

16 bit

大模型中最常见的浮点格式。BF16 通常更适合训练稳定性；FP16 / BF16 权重都约占 2 bytes / 参数。

INT8
1B

8 bit

常用于量化推理，可明显降低权重显存；实际占用还包含量化尺度、元数据和运行时开销。

INT4
0.5B

4 bit

常用于低成本推理。理论权重为 0.5 byte / 参数，但实际文件和显存通常会略高于理论值。

单位含义直觉理解

INTInteger，整数只能表示离散值，更省空间

推理

推理就是用已经训练好的模型生成结果。显存主要来自模型权重、KV Cache、临时激活和框架运行时开销。

📦 模型本身

这是必须先放进显存的部分，也是最容易心算的最低占用。例如 8B 的 FP16 模型约占 16GB。

💬 聊天缓存（KV Cache）

模型为了记住前文，会保存一份“聊天记录”。上下文越长、同时服务的人越多，这部分越大，不能按模型大小固定乘一个百分比。

🧰 临时工作空间

模型计算时还会临时占用一些显存，类似工作台。大小受 batch、序列长度和推理框架影响。

Transformer

看全文再理解

几乎所有现代大模型都是 Transformer 变体。Attention 是核心机制，让模型处理当前信息时，动态关注最相关的上下文。

Attention

Query · Key · Value

模型把每个 token 映射成三样东西：Query 表示我现在想找什么，Key 表示我能被怎样匹配，Value 表示我真正包含的内容。

训练

推理只需要“使用模型”；训练还要记录模型如何学习，所以同一个模型，训练通常比推理占用多得多。

📦 模型本身

当前版本的模型参数，必须放在显存中。

梯度

衡量每个参数对错误的影响有多大。

3

🧭 学习方向记录

Adam / AdamW 会为每个参数保存两份历史记录，用来判断下一步往哪里调整。专业名称叫“优化器状态”，通常约 8 bytes / 参数。

4

📝 解题草稿（激活）

训练时要保留前向计算过程，方便反向传播。batch 越大、文本越长，这份“草稿”通常越大。

一句话理解：推理像“打开一本书阅读”；训练像“边读、边做笔记、边修改原稿，还要保留修改历史”。因此全量训练时，模型每个参数常常不是只占 2 bytes，而是合计约 16 bytes，再加训练草稿和临时空间。

显存需求估算

以下是便于心算的数量级估算。GB 按十进制计算；实际运行还要预留框架、通信和显存碎片等开销。

Inference

推理显存

推理显存 ≈ 模型本身 + 聊天缓存 + 临时工作空间

  • FP16 / BF16 模型本身：参数量（B）× 2 ≈ GB
  • INT8 权重：参数量（B）× 1 ≈ GB；INT4 理论值 × 0.5
  • KV Cache 取决于上下文、batch 和模型结构，不按权重百分比硬套
  • 实际部署建议在估算值之上预留约 10%–20% 运行空间
Training

训练显存

全量训练（AdamW）≈ 16–20 bytes / 参数 + 激活

  • 常见拆分：权重 2B + 梯度 2B + FP32 主权重 4B + Adam 状态 8B
  • 仅参数相关状态，70B 就约 1.12TB（按 16 bytes / 参数）
  • 激活取决于 batch、序列长度和梯度检查点，可能再增加大量显存
  • ZeRO、FSDP、张量并行和 offload 会改变每张卡的实际占用

Offload 与并行

Offload 会把部分权重、梯度或优化器状态放到 CPU 内存或 NVMe；并行则把模型状态和计算拆到多张 GPU。它们能降低单卡需求，但会引入通信、带宽和速度成本。多卡总显存够用，也不代表任意卡数都能高效运行。

重要

GB 与 GiB 不完全相同

厂商和模型文件通常用十进制 GB：1GB = 10⁹ bytes；系统工具有时显示二进制 GiB：1GiB = 2³⁰ bytes。因此“1B 个 FP16 参数 = 2GB”约等于 1.86GiB。

70B FP16 / BF16 推理

模型本身先占约 140GB

  • 70B × 2 bytes = 140GB（约 130GiB）
  • 这只是把模型“装进去”的最低空间
  • 聊天缓存和临时工作空间还要继续占显存，所以 2 × 80GB 通常非常紧张
70B 全量训练 · AdamW

仅“模型 + 学习记录”就约 1.12TB

  • 70B × 16 bytes ≈ 1.12TB
  • 这里的 16 bytes 包含模型、梯度、主副本和 Adam 的学习记录
  • 还没算训练草稿、临时缓冲和通信空间，因此实际会更高

一张 GPU 大概能放下多大的模型？

下面只比较“模型本身”的理论容量，方便快速判断。真正运行时还要给聊天缓存和临时工作空间留余量。

GPU显存单卡大致可容纳怎么理解
RTX 409024GB7B FP16；14B INT4适合个人开发和本地体验
RTX 509032GB14B FP16 较紧；32B INT4消费级单卡中的大显存选择
A100 / H10080GB32B FP16；70B INT8 较紧数据中心训练和推理常用
H200141GB70B FP16 的模型本身仍需为 KV Cache 和运行空间留余量
B200192GB70B FP16，并有较充足余量Blackwell 数据中心 GPU
B300288GB100B FP16；更大的量化 / MoE 模型Blackwell Ultra，面向大型推理与训练
GB300 不是一张显卡。 GB300 Grace Blackwell Ultra 是把 Grace CPU 和 Blackwell Ultra GPU 组合起来的平台；GB300 NVL72 是机架级系统，包含 72 颗 GPU、36 颗 Grace CPU，总 GPU 显存最高约 20TB。不要把它与“单张 B300 288GB”混为一谈。

简单判断：先用“参数量 × 每参数字节数”算模型本身，再挑显存更大的 GPU，并额外留出运行空间。多卡相加只是容量下限，实际还要看并行方式、通信速度和软件支持。

简单做个题

用同一套估算框架，快速判断模型能不能跑、需要多少卡。

题目 1：推理

场景：一个 32B 模型，FP16 / BF16，推理。

  • 仅模型本身大约需要多少显存？
  • 如果用 RTX 4090（24GB）推理，容量下限是多少张卡？
查看答案与解析
答案：模型本身约 64GB；至少 3 张 4090 才达到容量下限。

计算：32 × 2 = 64GB。两张 4090 只有 48GB，装不下；三张合计 72GB，刚超过模型本身。

但注意：72GB 只比 64GB 多 8GB，还要容纳 KV Cache、临时工作空间和框架开销，因此工程上可能仍然很紧张。更稳妥的方案是更多显存、量化，或使用专业数据中心 GPU。

题目 2：训练

场景：一个 14B 模型，混合精度全量训练，AdamW。

  • 先不算训练草稿，模型和学习记录大约需要多少显存？
  • 使用 A100 40GB 时，容量下限是多少张？
查看答案与解析
答案：约 224GB；容量算术下限为 6 张 A100 40GB。

计算：14 × 16 = 224GB；224 ÷ 40 = 5.6，因此至少向上取整为 6 张。

为什么实际通常更多：224GB 还没有包括训练草稿（激活）、临时缓冲、通信空间和显存碎片。ZeRO / FSDP 能把模型和学习记录拆到多张卡上，梯度检查点则可以减少训练草稿。

题目 3：卡数判断 / 可行性

场景：4 张 H100 80GB，一个 100B 模型，FP16 / BF16。

  • 推理时，仅看模型本身是否放得下？
  • 全量训练时，容量下限大约需要多少张 H100 80GB？
查看答案与解析
答案：推理容量上放得下；训练参数相关状态的下限约为 20 张。

推理：100 × 2 = 200GB；4 张 H100 总显存为 320GB，因此模型本身有空间放下，还剩约 120GB 给 KV Cache、临时工作空间和框架开销。但还必须确认并行方式和卡间通信。

训练：100 × 16 = 1600GB；1600 ÷ 80 = 20 张。这仍然没有包括训练草稿和临时开销，因此实际卡数通常更多，或必须配合 ZeRO / FSDP、梯度检查点与多机并行。
